## The spec

A working HTML mockup in `apps/desktop/design/simple/`: `simple.css` (tokens, each component's look, layout), `core.js` (data, the face), `side.js`, `chat.js`, `panel.js`, `modals.js`, `sheets.js`, `settings.js`, `more.js` (call, versions, logins, computer size, what's new, feedback, island), `vm.js` (the agents' computer screen), `ui.js` (components). Serve it with `node apps/desktop/design/serve.mjs` only if you really must; reading the files is enough.

Reproduce the **look and behaviour** with the app's real components and data. Do not paste the mockup. Use the app's tokens (`bg-s1/s2/s3`, `text-ink…ink4`, `border-line`, `text-red/green/amber/blue`, radii), not the mockup's CSS variables.

Look: quiet, hairlines over filled boxes, regular weights, sentence case, white (ink) for the primary action, colour only where an agent or a brand is, small crisp motion (`rise`, `pop`, hover lifts). No yellow accent bars, no decorative gradients, nothing that reads as generic AI UI.

## Already built, use it

- `components/Face.tsx`, `AgentTile.tsx`: an agent's face. - `components/ui/*`: button, switch, segmented, input, dialog, sheet, dropdown-menu, tooltip, toast. `components/Dither.tsx`, `PixelBanner.tsx`, `lib/dither.ts`: the dithered pixel field.
- `lib/kit.ts`: typed wrappers for every backend command. All exist now in `src-tauri/src/kit_cmds.rs`. A command can still reject (no Lima, no key): catch it and show the screen's empty state.

## Rules

- Edit only the files of your surface. Another agent owns the rest. A tiny edit in `src/App.tsx` or `src/App.css` is allowed to wire something: re-read the file right before editing, keep it minimal. New CSS goes in a new file under `src/styles/` that you `@import` from `App.css`.
